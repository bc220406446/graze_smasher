Privacy, Data Use & Algorithmic Ethics Policy

How Graze Smasher collects review metadata, processes IP velocity heuristics, analyzes linguistic patterns with ML ensembles, and safeguards consumer trust.

1. Purpose and Overview

Graze Smasher is an academic research and engineering prototype developed for the CS619 final-year computer science project. Its primary purpose is to safeguard consumer decision-making by identifying deceptive, machine-generated, and incentivized fake reviews on modern e-commerce platforms using a multi-tier machine learning ensemble.

Transparency, consumer privacy, and algorithmic accountability are foundational to this tool. This policy explains what information is collected when reviews are submitted or ingested, how IP-based velocity detection works, how automated machine learning classifications are generated, and what ethical protections exist against unfair misclassifications.

2. Data Collected & Storage Purposes

When users or external platforms interact with Graze Smasher, the system stores the following data points:

Data Point Purpose & Usage Retention Policy
Review Text & Rating Vectorized for TF-IDF n-gram text modeling, linguistic feature extraction, and TextBlob sentiment polarity analysis. Retained alongside the product to compute community authenticity metrics.
Client IP Address Evaluated by sliding-window velocity heuristics to detect review spamming bursts and automated submission bots. Retained strictly for fraud mitigation and audit tracking. Never sold or shared.
User Account Data Username, email, and password hash (PBKDF2 SHA-256) used for authenticated role-based access. Retained until user profile deletion is requested.
ML Model Scores Calibrated SVM probability, J-48 tree classification score, TextBlob polarity, and composite authenticity scores. Persisted to provide transparent explainability badges to consumers.

3. IP Address Velocity Heuristics & Bot Mitigation

Fraudulent review syndicates often employ bot farms or incentivized review rings that submit dozens of fraudulent reviews from the same network origin in a short span of time. To counter this without requiring intrusive browser fingerprinting, Graze Smasher implements a sliding-window IP velocity detector:

The Velocity Rule Engine
  • Each incoming submission logs its client IP address and exact timestamp in an in-memory sliding tracker and database record.
  • If the same IP address exceeds N reviews within a rolling W-minute window (configurable via the Admin Control Panel), the review is automatically flagged as suspicious (ip_flag = True).
  • Flagged reviews incur a 20% penalty in the composite authenticity formula and trigger automated system alerts if high concentrations are reached.
Demo & Dataset Notice: The underlying evaluation dataset (Salminen et al., 2022) does not contain real-world IP addresses. For testing and demonstration purposes, synthetic, clearly labeled simulated IP addresses from the RFC 5737 documentation blocks (e.g., 192.0.2.x, 198.51.100.x) are generated to demonstrate multi-tenant velocity monitoring.

4. Algorithmic Fairness & Human-in-the-Loop Oversight

Automated machine learning models are inherently statistical approximations. While the Graze Smasher ensemble achieves over 90% empirical accuracy on benchmark datasets, automated systems must never make irreversible or punitive determinations without recourse:

Multi-Signal Ensemble

No single feature decides an outcome. Decisions synthesize n-gram lexical patterns (Calibrated LinearSVC), 8 behavioral/structural features (J-48 Tree), sentiment-rating discrepancies (TextBlob), and network velocity into a single weighted score.

Human-in-the-Loop Override

System administrators maintain access to a Flagged Content Moderation Queue. Legitimate customer reviews incorrectly flagged as fake can be manually inspected, verified, and overridden with a single click.

Graze Smasher categorizes reviews into three confidence tiers: Genuine (≥ 70%), Suspicious (40% - 69%), and Fake (< 40%). Suspicious reviews remain visible to shoppers with a caution indicator rather than being unconditionally suppressed.

5. Security, User Rights & Project Contacts

  • Cryptographic Security: Passwords are protected using standard PBKDF2 hashing with SHA-256 signatures. Sensitive keys are stored in environment variables, and CSRF protection is active across all forms.
  • Right to Deletion: Registered reviewers may delete their accounts and submitted reviews at any time through their user profile or by contacting an administrator.
  • Academic Context: This system was created as an educational final-year project at the Department of Computer Science (CS619). For inquiries or demonstration feedback, refer to the project documentation in the repository.
