Privacy & Data Use Policy

Information regarding review metadata collection, ML processing, and algorithmic transparency in Graze Smasher.

1. Purpose & Overview

Graze Smasher is an academic research and engineering prototype developed for the CS619 final-year project. Its objective is to protect consumer decision-making by identifying deceptive, bot-generated, and incentivized fake reviews on e-commerce platforms using a multi-tier machine learning ensemble.

Transparency, consumer privacy, and algorithmic accountability are key priorities. This policy outlines what data is collected, how IP-based velocity detection works, and how automated machine learning classifications are generated.

2. Data Collected & Usage

When users or external platforms interact with Graze Smasher, the system processes the following data points:

Data Point Purpose & Usage Retention Policy
Review Text & Rating Vectorized for TF-IDF n-gram text modeling, feature extraction, and TextBlob sentiment analysis. Stored with the product to compute community authenticity metrics.
Client IP Address Evaluated by sliding-window heuristics to detect spamming bursts and automated submission bots. Used strictly for fraud mitigation and audit tracking. Never sold or shared.
User Account Data Username, email, and password hash (PBKDF2 SHA-256) for authentication and role-based access. Retained until user profile deletion is requested.
ML Model Scores Calibrated LinearSVC probability, J-48 tree score, TextBlob polarity, and composite authenticity scores. Persisted to provide transparent explainability for evaluated reviews.
3. IP Velocity Heuristics & Bot Mitigation

To detect review syndicates and automated submission bursts without invasive browser fingerprinting, Graze Smasher monitors submission velocity:

  • Each incoming review submission tracks its client IP and submission timestamp.
  • If the same IP address exceeds the configured threshold within the rolling time window, the review is automatically marked with an IP burst warning.
  • Flagged reviews receive an adjustment in the composite score and appear in administrative inspection queues.
Dataset Note: The evaluation dataset (Salminen et al.) does not include real personal IP addresses. Simulated IP addresses from documentation ranges (RFC 5737) are utilized for demonstration purposes.
4. Algorithmic Fairness & Moderation

Automated classifications are statistical estimates. Graze Smasher incorporates checks to prevent unfair penalties:

  • Multi-Signal Ensemble: Classifications synthesize lexical n-grams (LinearSVC), behavioral features (J-48 Tree), sentiment-rating divergence, and IP velocity.
  • Transparent Tiers: Reviews are categorized into Genuine (≥ 70%), Suspicious (40% - 69%), and Fake (< 40%). Borderline entries remain visible with a caution notice rather than silent suppression.
  • Administrative Moderation: Platform administrators can review flagged content and manually override classifications where necessary.
5. Security & Contact
  • Security: Standard PBKDF2 password hashing with SHA-256 is used for account credentials. CSRF protection is active across all forms.
  • Account Management: Users may update their profile information or request account deletion through their profile settings.
  • Project Context: This application was built for academic research as part of the CS619 final-year project.
